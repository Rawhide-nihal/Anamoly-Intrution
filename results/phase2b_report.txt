==============================================================================
PHASE 2B — DBSCAN (TRANSDUCTIVE DENSITY-BASED ANOMALY DETECTION)
==============================================================================

1. OBJECTIVE
  Assess whether density-based clustering separates attack traffic from benign traffic in
  CIC-IDS2017 by labelling low-density points (DBSCAN noise, label -1) as anomalies, using
  only unlabelled flow features for every modelling decision.

2. WHY DBSCAN
  DBSCAN needs no number of clusters, finds arbitrarily shaped dense regions, and has an
  explicit 'noise' concept: points that are neither core points nor within eps of one.
  Under the hypothesis that attack flows lie in sparse regions of feature space, noise is
  a natural binary anomaly indicator.

3. HOW DBSCAN DIFFERS METHODOLOGICALLY FROM ISOLATION FOREST
  * TRANSDUCTIVE: DBSCAN labels only the rows it is run on. sklearn's DBSCAN has no
    predict(); there is no trained model to apply to unseen traffic, so these results do
    not demonstrate out-of-sample generalisation.
  * Unsupervised over a mixed sample: DBSCAN clusters a uniform random sample that contains
    both benign and attack rows (labels hidden), rather than learning from benign-only data.
  * Output is binary (noise vs clustered). No continuous anomaly score is produced, so
    ROC-AUC is not reported; no score is manufactured from cluster ids.
  * Distance-based: results depend on the scale of every feature, so standardisation is
    essential here (a property of DBSCAN's Euclidean neighbourhoods, not a claim about
    Isolation Forest).
  * Cost grows with the number of neighbour pairs (roughly quadratic in n for dense data),
    which forces sampling.

5. PREPROCESSING
  Features: 70 (78 numeric - 8 confirmed zero-variance columns); Destination Port retained.
  ±inf -> NaN; median imputation; StandardScaler. Imputer and scaler were fitted on the
  working sample's features only (no labels). The frozen Phase 2A imputer/scaler were NOT
  reused: they were fitted on BENIGN-only training rows, a label-based selection that would
  let labels shape DBSCAN's distance metric.
  Rows with NaN before imputation: 37. Columns constant within the working sample: none.
  Checks: no NaN, no inf, shape (50000, 70), finite standardized matrix: PASS.

6. k-DISTANCE / eps SELECTION (unsupervised)
  For each min_samples m, the distance from every point to its m-th nearest neighbour
  (counting itself, matching sklearn's core-point definition) was sorted and the elbow located
  with Kneedle. Three variants were computed; the k-distances span ~5 orders of magnitude:
    min_samples= 5: log10 eps=2.335 @96.7th pct | linear eps=5.639 @99.4th pct | trunc99 eps=0.526 @83.9th pct
    min_samples=10: log10 eps=2.552 @95.7th pct | linear eps=7.304 @99.4th pct | trunc99 eps=0.781 @84.1th pct
    min_samples=20: log10 eps=3.219 @95.5th pct | linear eps=7.836 @99.0th pct | trunc99 eps=1.085 @83.8th pct
  Stability of each rule under label-free perturbations (min_samples=10):
    log10    full=2.552 trim0.1%=2.061 trim1%=1.990 half-sample=3.335  max/min=1.68
    linear   full=7.304 trim0.1%=1.805 trim1%=0.781 half-sample=8.147  max/min=10.44
    trunc99  full=0.781 trim0.1%=0.764 trim1%=0.600 half-sample=1.073  max/min=1.79
  Selected rule: Kneedle on the log10 k-distance curve. It is invariant to rescaling of
  distances and is the most stable rule above; the linear rule is set by a handful of extreme
  points (its eps moves >10x when the top 0.1-1% of points is trimmed), and the truncated rule
  depends on an arbitrary truncation level. The transition region spans roughly
  eps 0.78 - 7.30; the chosen eps lies inside it.
  eps was NOT chosen using precision, recall, F1, accuracy or any label.

7. min_samples SELECTION
  Candidates [5, 10, 20] were fixed in advance. Primary min_samples = 10: the
  candidate closest to ln(n) = 10.82, a common data-size heuristic. The 2*dim
  heuristic (140 for 70 features) was not used: it implies a much larger eps whose neighbour
  storage is infeasible here; 5 and 20 are reported in the sensitivity analysis.

13. LIMITATIONS
  * DBSCAN is TRANSDUCTIVE: noise labels exist only for the clustered rows; no predict() and
    no evidence of generalisation to unseen traffic.
  * The experiment uses a representative uniform sample (50,000 rows), not all 2,522,362
    deduplicated observations; neighbourhood storage grows ~quadratically with n.
  * Noise assignment is sensitive to eps and min_samples (Section 10); the elbow itself is
    ill-defined on this heavy-tailed k-distance curve (three reasonable rules disagree).
  * In 70 dimensions Euclidean distances concentrate and are dominated by heavy-tailed
    standardized features; local density is harder to estimate reliably.
  * PCA changes local-density relationships: truncation removes low-variance directions in
    which some flows may be isolated, so noise sets differ across spaces.
  * Rare attack categories (e.g. Heartbleed, Infiltration, SQL Injection) are absent or have
    very few rows in a uniform sample; their percentages are unstable or unavailable.
  * Median imputation and StandardScaler were fitted on the same rows being clustered
    (consistent with the transductive design).
