    rows with zero 10-NN distance                0          1,205
  Assessment: the elbow is ambiguous in BOTH spaces — the three Kneedle variants disagree by
  ~9x (WITH) and ~10x (WITHOUT), and the log10 knee is weaker WITHOUT Port
  (0.218 vs 0.271). The WITHOUT-Port curve is also LESS stable under the
  label-free perturbations: trimming the top 1% sends the log10 knee to the 1e-6 floor (eps=1e-06;
  other perturbations 2.55-3.67). Cause: removing Destination Port makes 2,872 rows
  feature-identical (WITH Port: 0), giving 1,205 zero k-distances that the Phase 2B
  procedure floors at 1e-6; this flat block can dominate the normalised log curve. The full-curve
  eps (3.100) used here is unaffected by that perturbation, but it is less robust than the
  WITH-Port eps. No clean elbow is claimed.

12. INTERPRETATION (neutral; no configuration is a 'winner')
  Q1 Isolation Forest: Removing Destination Port changed Isolation Forest's scores and/or metrics beyond the pre-declared threshold (|delta| >= 0.01 or Pearson < 0.99): ROC-AUC +0.0058, recall -1.13 pp, FPR +0.48 pp, Pearson 0.997, 12,197 predictions changed.
  Q2 DBSCAN density structure: the selected eps moved 2.552 -> 3.100, clusters 56 -> 44, largest cluster 36,489 -> 36,916; attack rows in attack-dominated clusters 41.0% -> 39.8%, in mixed clusters 56.1% -> 58.1%.
  Q3 DBSCAN noise membership: the noise sets are partially different (Jaccard 0.712); 464 of 50,000 rows changed noise/non-noise assignment.
  Q4 Category-level: changes of >= 5 pp (stable-n categories only) — Isolation Forest: DoS GoldenEye 49.1%->60.2%; DBSCAN: DoS GoldenEye 23.7%->11.1%.
  Q5 Interpretation of the DBSCAN/Isolation Forest difference: in both feature spaces the
  majority of DBSCAN attack rows sit inside clusters rather than in noise (1.2% noise without Port vs 2.1% with), so the Phase 2B observation that most attack
  rows occur in dense regions persists after removing Destination Port. This is a description of the ablation only;
  the formal DBSCAN-vs-Isolation-Forest comparison is deferred.

13. LIMITATIONS
  * One feature removed, one configuration per algorithm; IF uses one random seed (random_state=42) — with a
    different feature count the trees draw different splits, so part of any IF change is seed variation.
  * DBSCAN is transductive and evaluated on a 50k sample; eps had to be re-selected, so the DBSCAN
    comparison combines the feature change with the change in the unsupervised eps.
  * The k-distance elbow is ambiguous in both feature spaces; noise sets are sensitive to eps (Phase 2B).
  * The Phase 2B log10 rule floors zero k-distances at 1e-6; without Port, feature-identical rows make
    the rule unstable under trimming (Section 7). The procedure was kept unchanged for comparability.
  * Rare categories (Heartbleed, Infiltration, SQL Injection, XSS) give unstable or no estimates.
  * Timing comparisons come from separate runs on a shared machine.
